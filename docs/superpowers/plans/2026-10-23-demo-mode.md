# Demo mode: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a demo of the real Stage 1 app. It runs on built-in sample data saved in the browser, with no Supabase and no login, and is published at `/Third-Place-Berlin/demo/`.

**Architecture:**
- **The demo is a Vite build mode (`--mode demo`).** In that mode, `vite.config.ts` aliases every `src/data/*.ts` module to a twin in `src/demo/data/*.ts` with the same exports. It also aliases `src/lib/supabase.ts` to a stub that throws, and `src/demo/slot.tsx` (empty in the real build) to `src/demo/slot.demo.tsx`, which holds the ribbon and the demo controls.
- **The real build never resolves the demo files,** so no demo code ships in the real app.
- **Twins share one store.** The `src/demo/data` twins read and write a single in-browser store (`src/demo/store.ts`, saved in `localStorage`). They apply the backend's main rules (`src/demo/rules.ts`) and notify subscribed React hooks.
- **Sample timestamps shift forward** by the days since the first visit. Anything the user creates keeps its real time.

**Tech Stack:** React 18, TypeScript, Vite 5 + vite-plugin-pwa, Vitest + Testing Library (jsdom), React Router (HashRouter), GitHub Actions → GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-10-23-demo-mode-design.md`

## Global Constraints
- Branch `demo-mode`. **Push and publish only on Nella's explicit "push it live".**
- The existing **52 app tests and 176 SQL checks stay green**: `npm test` and `npm run test:db` in `app/`.
- **The real build (`npm run build`) contains no demo code or sample data,** and the demo build (`npm run build:demo`) contains no Supabase client. Task 9 checks both by grepping the bundles.
- **Demo address and identity:**
  - URL: `https://nelladelva.github.io/Third-Place-Berlin/demo/`, with base `/Third-Place-Berlin/demo/`
  - PWA name "Third Place Berlin Demo", short name "TPB Demo", `id`/`scope`/`start_url` = the demo base
  - storage key prefix `tpb-demo:`
  - The demo must never touch the real app's storage keys (e.g. `tpb.invite`, Supabase auth keys).
- **A "Demo · sample data" ribbon** shows on every screen of the demo.
- **The person:** id `demo-you`, display name "You (demo)", starting as **admin**. The switch in *Me* flips to **member**.
- **Sample content:**
  - The 8 circles exactly as in `app/supabase/seed.sql`: name, emoji, colour, visibility, description. Women Events is closed.
  - About 15 fictional members, with `avatarUrl: null` (initials) and no email anywhere.
  - 4–6 upcoming meetups at real Berlin places, including **"Tempelhof picnic"** with the sign "yellow blanket by the big tree".
  - Sample text is in English only. The interface stays EN/DE.
- **Main flows behave for real**, including their inbox notifications, as in spec §"How closely". Notification `kind`s come from `supabase/functions/_shared/payload.ts`: `meetup_new | poll_new | mention | reply | message_new | member_approved | join_request | join_decided | proposal_new | proposal_decided | recommended`.
- **Publishing:** the workflow builds the demo on every push to `main`, and builds `/app/` **only when `vars.VITE_SUPABASE_URL` is set**.

## Review Focus
1. **An old saved demo after a demo update** (a store `version` mismatch, or a corrupt JSON): the demo must reset to the seed cleanly, never crash or show a blank screen. *Test in Task 3.*
2. **`localStorage` unavailable** (private mode, quota exceeded, a throwing setter): the demo works in memory for that visit. *Test in Task 3.*
3. **Switching Admin → Member while on the admin console** (`#/me/admin`): no crash, the admin screens disappear, and the admin entry is hidden. *Test in Task 7.*
4. **Many days between visits:** sample meetups stay upcoming and sample chats look recent. A meetup the user created in the past ends and disappears, as in the real app. *Test in Task 3.*
5. **Bundle leakage either way:** the real `dist/` must not contain demo sample strings, and `dist-demo/` must not contain the Supabase client. *Checked in Task 9.*

### Task 4: Demo rules (the backend's main flows)

**Files:**
- Create: `app/src/demo/rules.ts`, `app/src/demo/rules.test.ts`

**Interfaces:**
- Consumes: `DemoState`, `newId` and `nowIso` from Task 3.
- Produces pure functions `(s: DemoState, …args) => result`, which mutate `s`. Each notification is pushed as `{ id, userId, kind, data, createdAt, read: false, sample: false }`:
  - **Circles:**
    - `joinCircle(s, circleId)`: open circles only, otherwise throws `'closed'`.
    - `leaveCircle`.
    - `requestJoin(s, circleId)`: closed circles; creates a `join_request` notification for the circle's hosts and admins.
    - `recommend(s, circleId, userId)`: a `recommended` notification for that user.
    - `decideJoin(s, requestId, approve)`: on approve adds a member; a `join_decided` notification either way.
  - **Meetups:**
    - `createMeetup(s, input)`: the host is auto "Going"; a `meetup_new` notification for the circle's members.
    - `rsvp(s, id)`: returns `'going' | 'full'` (full when `capacity` is reached).
    - `cancelRsvp`, `cancelMeetup`, `updatePin`.
    - `checkIn(s, id)`: `'checked_in'` if going, otherwise `'not_going'`. Location and time are not checked.
  - **Chat:**
    - `postMessage(s, scope, body, opts)`: creates a `mention` notification for each mentioned user, and a `reply` notification for the replied-to author.
    - `react` (toggles), `deleteMessage` (marks deleted; only the author, a circle host or an admin).
    - `createPoll(s, circleId, question, options)`: a poll message plus a `poll_new` notification.
    - `vote` (one vote per person, changeable), `addPin`, `deletePin`, `report(s, targetType, targetId, reason)`.
  - **People:**
    - `vouch(s, pendingId)`: adds a vouch. At `settings.vouchesRequired` it approves: the status becomes member, plus a `member_approved` notification.
    - `approveMember`, `removeMember`.
    - `setAdmin`, `block`, `unblock`.
  - **Admin:**
    - `openLaunch(s)` returns a code. `closeLaunch`, `setVouchesRequired`.
    - `proposeCircle(s, input)`: a `proposal_new` notification for the admins.
    - `decideProposal(s, id, decision, note)`: `'approved'` creates the circle; a `proposal_decided` notification for the proposer.
    - `resolveReport`, `removeReportedContent`, `setVisibility`, `setHost`, `archiveCircle`.
- **Permission rule:** admin-only functions throw `'not_admin'` when `s.me.viewAs === 'member'`.
